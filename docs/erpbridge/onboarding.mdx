# ERPBridge onboarding guide

> Connect an ERP system to ERPBridge with the `bridgectl` CLI.

## Prerequisites

Verify that you have the following installed:

| Requirement | Purpose |
|---|---|
| Docker and Docker Compose | Runs ERPBridge Server and mock-erp |
| Go 1.26.2+ | Needed to build `bridgectl` (if not pre-built) |

:::note
This guide uses `mock-erp` from the repository. For your ERP, replace the `mock-erp` paths and ports with your OpenAPI specification and service address.
:::

## Step 1 — Start ERPBridge Server

Start the required services with Docker Compose:

```bash title="Start the stack"
docker compose up --build -d
```

Verify that the services are running:

```bash title="Check container status"
docker compose ps
```

ERPBridge Server is available at **`http://localhost:8080`**.

## Step 2 — Build `bridgectl`

If `bridgectl` is not in your project root, build it:

```bash title="Build via Makefile"
make build
```

Or build it manually:

```bash title="Build via go build"
go build -o bridgectl ./tools/bridgectl/main.go
```

:::tip
Skip this step if a pre-built `bridgectl` binary is already available in your PATH. See [bridgectl overview](../bridgectl/overview.mdx).
:::

## Step 3 — Register your ERP API

Register the connection details for your ERP system:

```bash title="Register the ERP endpoint"
./bridgectl api register \
  --name erp \
  --url http://localhost:8081 \
  --module erp \
  --description "Internal Mock ERP for testing"
```

**What each flag does:**

| Flag | Description |
|---|---|
| `--name` | Unique identifier for this API |
| `--url` | Base URL of your ERP service |
| `--module` | Logical grouping (for example `finance`, `hr`, `erp`) |
| `--description` | Human-readable description. This flag is required. |

:::warning The `--description` flag is required
It helps the LLM layer understand the purpose of the API. The command fails without it.
:::

## Step 4 — Generate tool schemas

Convert your ERP OpenAPI specification into MCP tool schemas:

```bash title="Generate and apply schemas from the pinned OpenAPI"
make generate-tools
```

The command writes one JSON schema file per generated tool into `schemas/erp/` (one directory per module), for example `schemas/erp/list_employees.json`. With `-o yaml`, it also prints one YAML sequence containing all generated tools to stdout.

:::tip Verify the pinned contract first
The Makefile downloads `https://raw.githubusercontent.com/nmdra/mockerp/v0.2.1/openapi.yaml` before generation.
:::

:::note
The `schemas/` directory is **not tracked by git**. Generate the schemas on each machine that runs `bridgectl`, or keep the files out of band.
:::

## Step 5 — Apply tools to the registry

Upload the schemas to ERPBridge Server. Point `apply` to the directory that the generator wrote.

```bash title="Apply all generated tools"
./bridgectl tool apply -f schemas/erp/
```

:::tip Apply generated YAML directly
The generator writes individual `.json` files to disk for verification and also supports a YAML manifest. If you redirect `bridgectl tool generate ... -o yaml` to a file, `bridgectl tool apply` applies every sequence item or YAML document in that file.
:::

## Step 6 — Verify the tools

Verify that the tools are registered:

```bash title="List registered tools"
./bridgectl tool get
```

You see your tools listed with a `READY` status. If any show another status, see the [Troubleshooting](#troubleshooting) section below.

## Manage tools

### Delete a tool

Remove a tool from the active registry when you no longer need it.

**Soft delete (default):**
Marks the tool as inactive and hides it from MCP clients. The tool stays in the database for audit.

```bash title="Soft delete"
./bridgectl tool delete [tool_name] [version]

# Example:
./bridgectl tool delete list_items 1.0.0
```

**Hard delete (permanent):**
Completely removes the tool from the SQLite database.

```bash title="Hard delete"
./bridgectl tool delete [tool_name] [version] --hard
```

:::danger
`--hard` deletes the tool from the database. You cannot restore it.
:::

:::note Restore a soft-deleted tool
To restore a soft-deleted (hidden) tool, apply its schema again:

```bash title="Restore a tool"
./bridgectl tool apply -f schemas/erp/list_items.json
```

:::

## Troubleshooting

### Connection refused when running CLI commands

**Error:**

```
apply failed: Get "http://localhost:8080/...": dial tcp 127.0.0.1:8080: connect: connection refused
```

**Cause:** ERPBridge Server is not running, or the CLI points to the wrong address.

**Fix:**

1. Verify that the Docker services are running:
   ```bash title="Check services"
   docker compose ps
   ```
2. Verify your CLI context:
   ```bash title="List contexts"
   ./bridgectl context list
   ```
3. If the address is wrong, override it with environment variables:
   ```bash title="Override server address"
   export BRIDGE_SERVER=http://localhost:8080
   export BRIDGE_MCP_SERVER=http://localhost:8080
   ```
   Or edit `~/.bridgectl/config.yaml` and change the `server` value of the active context.

### Registration fails with a missing flag error

**Error:**

```
required flag(s) "description" not set
```

**Cause:** The `--description` flag is required on `api register`.

**Fix:** Always include it:

```bash title="Register with description"
./bridgectl api register \
  --name erp \
  --url http://localhost:8081 \
  --module erp \
  --description "Internal Mock ERP for testing"
```

### OpenAPI specification not found

**Error:**

```
failed to load OpenAPI spec: open ...: no such file or directory
```

**Cause:** The path passed to `--openapi` does not match the actual file location.

**Fix:** Verify that the file exists from your current directory:

```bash title="Verify spec path"
ls mock-erp/openapi.yaml
```

Then rerun the generate command with the correct path.

### Tools are applied but calls return `internal server error`

**Cause:** ERPBridge Server cannot reach the ERP service, or the tool cannot reach Redis.

**Fix:** Verify the server logs for errors:

```bash title="Server logs"
docker compose logs erpbridge-server
```

Verify that the `mock-erp` and `redis` containers are healthy:

```bash title="Check containers"
docker compose ps
```

If a container is not healthy, restart it:

```bash title="Restart Redis"
docker compose restart redis
```

## Quick reference

```bash title="Day-to-day commands"
# Start services
docker compose up --build -d

# Build CLI
make build

# Register API
./bridgectl api register --name erp --url http://localhost:8081 --module erp --description "..."

# Generate and apply schemas from the pinned MockERP contract
make generate-tools

# Apply all tools
./bridgectl tool apply -f schemas/erp/

# Verify tools are READY
./bridgectl tool get

# Delete a tool (Soft - sets to HIDDEN)
./bridgectl tool delete [tool_name] [version]

# Delete a tool (Hard - permanent removal)
./bridgectl tool delete [tool_name] [version] --hard
```
