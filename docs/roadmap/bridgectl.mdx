# bridgectl roadmap

`bridgectl` is the developer toolchain for registering ERP APIs, managing MCP tool resources, and operating an ERPBridge deployment. The CLI ships with the `bridgectl-ops` agent skill for repeatable AI-assisted workflows.

## Shipped

| Area | Current capability | Technical reference |
| :--- | :--- | :--- |
| API and tools | `api`, `tool`, schema generation, validation, declarative apply, version inspection, and deletion. | [command overview](../bridgectl/overview.mdx) · [tool commands](../bridgectl/bridgectl_tool.md) |
| Operations | Cache statistics/flush, log tail/stats, contexts, shell completion, and version output. | [cache commands](../bridgectl/bridgectl_cache.md) · [log commands](../bridgectl/bridgectl_log.md) |
| Authentication | `token create`, `token list`, and `token revoke`, with token precedence across `--token`, `BRIDGE_API_TOKEN`, and the active context. | [Token commands](../bridgectl/bridgectl_token.md) · [API token guide](../erpbridge/tokens.mdx) |
| Agent workflow | The shipped `bridgectl-ops` skill covers onboarding, maintenance, authentication, observability, troubleshooting, and redacted bug reports. | [skill usage guide](../bridgectl/skills.mdx) |

## In flight

### CLI hygiene

Planned CLI work includes structured JSON log-tail filtering, server-side tool filtering, and atomic registry writes.
