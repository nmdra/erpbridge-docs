# Upgrade guide

The ERPBridge v0.3.0-alpha.1 compatibility contract shipped as the breaking
`@erpbridge/sdk` v1.0.0 release.

## MCP results are no longer flattened

`client.mcp.callTool()` and `client.tools.<name>()` now return `McpToolResult`,
the official MCP `CallToolResult` envelope. Text is not parsed as JSON and
content blocks are not moved into a REST-shaped `result` field.

Before:

```ts
const result = await client.tools.list_employees({})
console.log(result.result)
```

After:

```ts
const result = await client.tools.list_employees({})
console.log(result.content)
console.log(result.structuredContent)
```

`client.invoke()` and `client.registry.invoke()` remain REST operations and
continue to return `ToolResult` with a `result` field.

## Credentials are now active

The existing `token` and `tokenEnv` configuration fields now send bearer
credentials when set. Applications that passed these fields while they were
inert must account for the change. See [Authentication](./authentication.mdx)
for precedence, surface overrides, and the consume-only token lifecycle.

The default credential environment variable is now `ERPBRIDGE_TOKEN`.
`ERPBridge_TOKEN` remains a compatibility fallback when the canonical variable
is absent; migrate deployments to the all-caps name.
